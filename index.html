Production work

Internal team platforms

Real-time task board and workflow platform · used daily by the US and India teams

  • React
  • Node.js
  • Firebase Auth & Firestore
  • Redis
  • Vercel serverless
  • Security rules

The content and engineering teams were tracking work across spreadsheets and separate dashboards that disagreed with each other. I built the task board the content teams now run their work on, and a workflow platform that merges two live engineering dashboards into one.

How a request flows

  1. Sign inGoogle sign-in in the browser
  2. VerifyServerless API checks the ID token on every call
  3. AuthorizeRole and board access read from the roster, enforced on the server
  4. WriteChange stored, then recorded in an append-only activity log
  5. SyncEvery open browser updates live; dropped listeners reconnect with backoff

Decisions and lessons

  • Permissions live in the database rules and the API, not the UI. A review found two screens that computed the user's permission but never applied it, so signed-out visitors saw 217 editable fields. The writes were already refused by the rules, which made it worse: edits appeared, then silently vanished. I threaded the permission through every input and added a cheap regression check: count enabled inputs on each page while signed out.
  • An empty read must never trigger a write. When the database refused reads, two start-up seeders mistook the empty result for an empty board and re-wrote 491 rows. I removed every write-on-empty-read path, traced the exact batches from document create times, and built a clean-up that deletes a duplicate only when another copy of the same task survives.
  • The log is append-only and written after the change succeeds, so it never records edits the database rejected.

Image licence audit

Data pipeline + review dashboard · 31,000+ images across websites, mobile app and travel listings

  • Python
  • OpenCV
  • Supabase (PostgreSQL)
  • Next.js
  • REST APIs

The company needed to know, for every image it publishes, whether it holds a licence for it. Records were spread across several stock photo accounts and design tools, and most published files had been resized and renamed, so names could not be matched.

Pipeline, cheapest check first

  1. CollectEvery image URL from the websites, app content and listing APIs
  2. GroupPerceptual hashes merge copies of the same picture
  3. Licence historyPurchase records pulled from vendor APIs and exports
  4. Content matchORB features + RANSAC against vendor previews
  5. TraceDesign-tool files traced back to their source photos
  6. ReviewDashboard where a person signs off each open case

Decisions and lessons

  • Match by content, not by name. Resized and renamed copies still verify, which is what moved the numbers.
  • "Available from a vendor" is not "licensed by us". An image only counts once its ID is in our own purchase history. An early version accepted vendor listings, and screenshots of downloads being refused proved that wrong.
  • Human sign-offs are stored apart from the automated sync, so re-running the pipeline can never overwrite a reviewer's decision.

Real-time voice AI avatar

Voice layer of a live video avatar product

  • React
  • Express
  • Web Audio worklets
  • Deepgram
  • GPT-4o
  • Gemini
  • ElevenLabs TTS

A video avatar that holds spoken conversations. The most reported bugs were in the voice loop: it talked over people, heard itself, and sometimes went silent.

The voice loop

  1. ListenVoice activity detection runs in the browser in an audio worklet
  2. TranscribeStreaming speech-to-text (Deepgram)
  3. AnswerServer calls the LLM chain with a short-reply prompt
  4. SpeakText-to-speech with lip sync; mic muted while it talks
  5. FilterEcho of its own voice is discarded before the next turn

Decisions and lessons

  • Silence is the worst failure. I added a provider fallback chain (OpenAI → Gemini → a scripted spoken line), so quota limits or an outage degrade the answer instead of killing the conversation.
  • Cost is a product metric. I built an admin dashboard with per-session cost in USD; the same stack was later reused for a second product.

Tour map automation

Desktop app for a mapping team · bookings in, finished maps out

  • Python
  • Playwright
  • OpenRouteService
  • Spatial indexing
  • pytest

Each motorcycle tour booking was turned into a Google My Maps route by hand: hotels, rental offices, daily routes and stops. The team already had thousands of hand-made maps, which became the training data.

Pipeline

  1. ReadHotel voucher PDFs and the itinerary text
  2. PinHotels and offices from the team's own past pins, then geocoders
  3. MatchCandidate routes from a spatial index over 3,803 past maps
  4. RouteRouting engine only where no past route fits
  5. Self-checkOutput re-read the way the mobile app reads it; problems listed for review

Decisions and lessons

  • Reuse the team's judgement. Past routes encode scenic choices that a shortest-path router would never make, so they are tried first.
  • Every fix is general. No tour-specific rules; each review comment became logic that applies to any map, plus a test.
  • Built for someone else's PC: self-updating installer, and a one-click error log the user can send when something fails.

Godown: invoice to inventory

Restaurant stock app · Code

  • FastAPI
  • MongoDB
  • React Native / Expo
  • TypeScript

Staff photograph a supplier invoice. A vision model reads each line, a matcher maps it to the catalogue and learns each supplier's shorthand from every correction, and stock only changes after a person confirms. Stock is derived from an append-only ledger, so every number can be explained. 71 API tests cover AI rate limits and checks that one restaurant can never see another's data.
